# 黑猫 AI 独立可迁移工作区实施方案

## 范围

本方案实现 `HEIMAO_PORTABLE_WORKSPACE_DESIGN.md` 在当前 Android + PRoot 架构下能够可靠实现的产品能力。

明确不承诺：敌对原生代码下的绝对隔离、硬件级资源配额、绝对防篡改审计、跨 CPU 架构二进制完全等价恢复。

## 实施原则

- 基于当前工作树已有的 Workspace/PRoot/Rootfs 安全改动最小合并，不覆盖或回退既有修改。
- 用户终端保持 `FULL_ROOTFS`；AI 继续使用无外部 App 挂载、无宿主伪文件系统的受限 Rootfs 通道。
- 旧会话无法可靠推断历史工作区时保持“未记录”，不得用助手当前绑定静默回填。
- 备份和恢复必须流式处理、校验后生效、失败可回滚。
- PRoot 只表述为防误操作和纵深防御，不表述为敌对代码强隔离。

## 阶段 1：固化运行边界基线

- 保持用户终端 `FULL_ROOTFS`。
- 保持 AI 通道不挂载 `/skills`、`/upload`、`/tool_outputs`、`/proc`、`/sys` 和外部目录。
- 验证 Rootfs staging、交换和失败恢复。

## 阶段 2：会话持久化工作区身份

- 数据库 Schema 27→28。
- `Conversation`/`ConversationEntity` 新增 `workspaceId`。
- 新会话捕获助手当前工作区；历史会话始终使用自身工作区。
- 工作区变化时清空 CWD；工作区缺失时显示明确状态，不回退到助手当前工作区。
- 会话分叉保留工作区；会话移动助手时不得静默切换工作区。

## 阶段 3：显式共享和改绑语义

- 工作区选择界面显示共享状态和绑定助手数量。
- 改绑助手只影响后续新会话，不批量修改历史会话。
- 解绑不删除工作区。
- 删除工作区后，历史会话保留缺失工作区身份，不自动串到其他工作区。

## 阶段 4：统一 AI 工作模式

- 模型不再看到 `sandbox/package` 参数。
- `workspace_shell` 统一使用当前工作区私有 Rootfs，可安装 apt、pip、npm、Go、Rust 和 CLI。
- 工作区内部文件与 Shell 工具固定免逐次审批。
- AI 通道继续保持最小挂载；用户终端继续使用完整 Rootfs 通道。

## 阶段 5：运行环境元数据

- 数据库 Schema 28→29。
- 记录 Rootfs 来源、SHA-256、大小、架构、发行版、安装时间和主要工具版本。
- 安装时流式计算摘要并检查架构兼容性。
- 环境扫描失败只记录警告，不把未知环境标记为可完整重建。

## 阶段 6：统一完整工作区备份格式

- WebDAV、S3 和本地导入导出共用一个归档服务。
- 归档包含 manifest、工作区元数据、`files`、`linux`、助手引用和会话引用。
- Rootfs 使用能够保留权限和链接语义的 TAR payload。
- manifest 记录格式版本、App/数据库版本、设备 ABI、长度和 SHA-256。
- 临时目录和 App 全局凭据默认不进入工作区备份。

## 阶段 7：校验、暂存、原子恢复与回滚

- 先下载到 partial 文件并完整校验。
- 解包到独立 staging，拒绝绝对路径、`..`、重复条目和链接逃逸。
- 同架构允许完整恢复；架构不匹配只允许恢复用户文件。
- 替换已有工作区必须明确确认，不静默合并。
- 目录、Room 和 Settings 更新失败时恢复旧目录、旧实体和旧引用。
- 旧版无 manifest 的备份继续按旧应用备份处理，但不得称为完整工作区备份。

## 阶段 8：应用侧审计、快照和软治理

- 数据库 Schema 29→30。
- 记录工作区、助手、会话、命令/文件操作、时间、结果、超时和退出码。
- 不记录完整 stdin、密钥和敏感环境变量。
- 审计明确标注为应用侧记录，不宣称绝对防篡改。
- 复用归档格式提供手动快照和恢复前快照。
- 提供磁盘统计、快照数量/总大小软阈值和清理确认，不宣称硬配额。

## 验收标准

- 助手改绑后，旧会话仍使用原工作区。
- 多助手显式绑定同一工作区时共享文件和环境；不同工作区不串用。
- AI 无需选择模式或逐次审批即可安装工具，且看不到外部 App 挂载。
- 完整备份恢复后，工作区文件、Rootfs、工具和引用一致。
- 损坏、截断、跨架构或恢复中断不会产生新旧混合状态。
- 所有数据库迁移、JVM 定向测试和 AndroidTest 源码编译通过；有设备时执行真实 PRoot 与恢复验收。
